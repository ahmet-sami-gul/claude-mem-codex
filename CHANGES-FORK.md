# Changes in claude-mem-codex

claude-mem-codex is an unofficial fork of [claude-mem](https://github.com/thedotmack/claude-mem) by Alex Newman, maintained by Ahmet Sami Gül. This file lists the modifications made relative to upstream **claude-mem 13.25.2 (commit `4e98d97`)**. It is the prominent notice of changed files required by section 4(b) of the Apache License 2.0; the per-commit history is in `git log 4e98d97..HEAD`.

Each area names the files it changes; `git diff --stat 4e98d97` in a clone of this repository gives the exhaustive list. The build output under `plugin/` is not edited by hand: it is regenerated from the sources below by `npm run build` (bundles in `plugin/scripts/` and `plugin/ui/`, the copied onboarding explainer in `plugin/skills/how-it-works/`, the package-derived fields of the `plugin/.claude-plugin/` and `plugin/.codex-plugin/` manifests, `plugin/hooks/hooks.json`, `plugin/hooks/codex-hooks.json`, `plugin/.mcp.json` and `plugin/package.json`). Some files under `plugin/` are hand-maintained sources that the build does not generate, and the fork modifies them directly: `plugin/scripts/bun-runner.js`, `plugin/scripts/version-check.js`, `plugin/skills/mode-creator/SKILL.md` and `plugin/skills/how-it-works/SKILL.md` (see [Publication as an unofficial fork](#publication-as-an-unofficial-fork)).

## Codex CLI observer provider

A new observation provider, `CLAUDE_MEM_PROVIDER=codex`, runs the memory observer on the user's local Codex CLI and ChatGPT plan (commits `83a129bc8`, `97900d2f6`, `a68ccf630`, `d703f6203`).

- **Locked-down invocation.** A closed argument builder for one-shot `codex exec` and the model-free probes, forbidden-argument assertions, TOML escaping and a model allowlist; an environment allowlist with drop lists and `CODEX_HOME` resolution; `CODEX_EXEC_SERVER_URL=none` for every Codex child; `--strict-config`, 53 `--disable` flags and the `agents.enabled`, `tools.update_plan`, `tools.experimental_request_user_input` and `skills.bundled` pins (codex-cli 0.156.1; re-validated on 0.160.0, which adds `daemon_auto_start` to the disables and tolerates `write_stdin_approval`, an approval safeguard for terminals the observer never has).
- **Exec runner.** Prompt on stdin with EOF, process-group kill, timeouts, an 8 MB output cap, a runtime tool guard that kills the process on the first tool attempt, and exit-code mapping. A tolerant JSONL parser accepts only answer and reasoning items; a single-answer rule keeps the last answer and audits the rest.
- **Self-check.** An asynchronous, single-flight lockdown verification with five model-free probes (`codex --version` in the tested range `>=0.160.0 <0.161`, `codex login status`, `codex debug models`, `codex features list`, `codex debug prompt-input` canary), a model/CLI minimum-version gate and a per-session jail check.
- **Executable resolution.** Fail-closed discovery of the native Codex binary (npm wrapper, macOS app bundles), with a fingerprint cache; Windows shims are refused.
- **Failure handling.** Failure classification with reset-time parsing and redaction; quota cooldowns that honor Codex's stated reset time; a non-blocking readiness gate with background re-checks and single-canary recovery; an observer resume scheduler that drains held sessions when a pause ends; dependency health for `codex_cli`; session-start messages that show the real resume time.
- **Worker wiring.** `CodexProvider`, opt-in hooks in `OpenAICompatibleProvider` (OpenRouter and Gemini stay byte-identical), provider dispatch that never silently downgrades Codex, Codex Telegram wrap-ups in `SessionRoutes`, an auxiliary process-registry role, a boot-time reaper for orphaned Codex processes, and an ingest guard that skips events from the observer jail.
- **Models.** Allowlist `gpt-5.6-luna` (default), `gpt-5.6-terra`, `gpt-5.6-sol`, `gpt-5.5`, `gpt-6-luna`, `gpt-6-sol`, `gpt-6-astra`.

Files: `src/services/worker/CodexProvider.ts`, `src/services/worker/codex/` (`codex-budget.ts`, `codex-env.ts`, `codex-errors.ts`, `codex-exec-runner.ts`, `codex-invocation.ts`, `codex-jsonl.ts`, `codex-metrics.ts`, `codex-prompt.ts`, `codex-self-check.ts`, `codex-transport.ts`), `src/services/worker/session/` (`codex-readiness-gate.ts`, `observer-resume-scheduler.ts`, `observer-turn-signal.ts`, `provider-error-policy.ts`), `src/shared/find-codex-executable.ts`, `src/supervisor/codex-orphan-reaper.ts` (all new); modified `src/services/worker/OpenAICompatibleProvider.ts`, `src/services/worker/provider-dispatch.ts`, `src/services/worker/http/routes/SessionRoutes.ts`, `src/services/worker/http/shared.ts`, `src/services/worker/dependency-preflight.ts`, `src/services/worker/field-optimizer.ts`, `src/services/worker/agents/ResponseProcessor.ts`, `src/services/worker-service.ts`, `src/services/worker-types.ts`, `src/services/server/Server.ts`, `src/shared/quota-cooldown.ts`, `src/shared/observer-health.ts`, `src/shared/dependency-health.ts`, `src/shared/find-claude-executable.ts`, `src/shared/oauth-token.ts`, `src/supervisor/process-registry.ts`, `src/sdk/output-classifier.ts`, `src/services/worker/onboarding-explainer.md`.

## Cost controls for ChatGPT plans

(commits `a6ecc411f`, `58f589991`, `20ef700ba`)

- **Exec budget.** `CLAUDE_MEM_CODEX_MAX_EXECS_PER_5H`: a sliding 5-hour call counter stored in `codex-usage.json` (timestamps and token counts only), refused before a slot is taken and paused/resumed through the quota breaker.
- **Batching.** No standalone init call, fresh generation per run, and batches of up to 4 observations (`CLAUDE_MEM_CODEX_BATCH_*`). Same-group batching (`SessionMessageBuffer.claimMatching`) takes the oldest waiting tool use plus the next ones of the same prompt, agent and working directory, skipping interleaved groups, never passing a summary request, and keeping in-group order.
- **Waiting-queue cap.** `CLAUDE_MEM_CODEX_MAX_QUEUED_OBSERVATIONS` (default 500 per session; 0 = off) drops the oldest waiting observations of a session, never in-flight work or summaries.
- **Subagent filter.** `CLAUDE_MEM_SUBAGENT_EVENTS` (`all`, `writes`, `none`) keeps subagent tool uses other than file edits away from the observer; they are still stored raw in the tool-use index.
- **Metrics.** Per-kind call counts, observations per call, token totals, tool attempts, budget refusals, dropped and skipped events in `/api/health`.
- **Prompt changes.** Exported envelope and reply rules, a batch prompt, and escaping of `observed_from_primary_session` tags inside tool fields and prior context for every provider.

Files: `src/sdk/prompts.ts`, `src/services/worker/SessionManager.ts`, `src/services/worker/SessionMessageBuffer.ts`, `src/services/worker/codex/codex-budget.ts`, `src/services/worker/codex/codex-metrics.ts`, `src/services/worker/http/shared.ts`, `src/shared/SettingsDefaultsManager.ts`, `src/shared/should-track-project.ts`.

## Settings API and viewer

(commits `97900d2f6`, `ee61eecbf`, `320247d7f`, `457c43e3d`)

- New `CLAUDE_MEM_CODEX_*` settings with per-key validation; cost levers, binaries, logins and the Codex home are file/env only.
- The unauthenticated `POST /api/settings` refuses to switch the provider to or from `codex`, validates security-relevant keys whenever they are present (provider, worker host/port, auth method), makes `CLAUDE_MEM_DATA_DIR`, `CLAUDE_CODE_PATH` and `CLAUDE_MEM_CLAUDE_CONFIG_DIR` file/env only, and answers a non-object body with 400.
- Viewer: a "Codex CLI" provider option that is selectable only in the direction the route accepts, a Codex settings block (model allowlist with warnings for small-allowance models, effort, verbosity, conversation budget, batch size, timeout; the exec cap and queue cap read-only), and no binary-path field.

Files: `src/services/worker/http/routes/SettingsRoutes.ts`, `src/shared/SettingsDefaultsManager.ts`, `src/ui/viewer-template.html`, `src/ui/viewer/App.tsx`, `src/ui/viewer/components/ContextSettingsModal.tsx`, `src/ui/viewer/constants/codex.ts` (new), `src/ui/viewer/constants/settings.ts`, `src/ui/viewer/hooks/useSettings.ts`, `src/ui/viewer/types.ts`.

## Publication as an unofficial fork

- **Marketplace.** The marketplace is renamed from `thedotmack` to `claude-mem-codex` (owner Ahmet Sami Gül); the plugin keeps the name `claude-mem`, so installs are `claude-mem@claude-mem-codex` and the data directory stays `~/.claude-mem`. The upstream `claude-mem-cowork` plugin (CMEM, Inc., streams to cmem.ai) is no longer listed. The Cursor marketplace manifest (`.cursor-plugin/marketplace.json`) and the root Grok plugin manifest (`.grok-plugin/plugin.json`) are removed: the Cursor and Grok Bot plugins they published run `npx -y claude-mem` (the official upstream npm package, which this fork does not publish) and default their remote MCP to cmem.ai. The `claude-mem-cursor/` and `claude-mem-grok-bot/` directories stay in the tree as upstream material. Every runtime path and id that named the upstream marketplace now uses `claude-mem-codex`: hook and MCP launcher root resolution (`src/build/hook-shell-template.ts`, `scripts/build-hooks.js`), `MARKETPLACE_ROOT` and worker-script resolution, the plugin-enabled check (`src/shared/plugin-state.ts` and the launcher's own copy in `plugin/scripts/bun-runner.js`), project-tracking skip, the MCP marketplace-marker check, the install-version marker, the npx installer and uninstaller (`knownMarketplaces`, `installed_plugins.json`, `enabledPlugins`, cache and data directories), host-integration installers, `scripts/sync-marketplace.cjs`, `scripts/restart-marketplace-worker.cjs`, `scripts/check-pending-queue.ts` and the bug-report scripts. `scripts/build-hooks.js` checks the cache fallbacks in `plugin/.mcp.json` only after `--write-shell-templates` has regenerated the launchers, so the rename can be rebuilt.
- **No upstream npx commands in runtime hints.** `npx claude-mem ...` runs the official upstream npm package, which only looks for the upstream marketplace install and offers to install upstream next to this fork. The observer-failure banner (`src/shared/observer-health.ts`) now offers the worker's own restart and doctor endpoints and the logs; the restart page's give-up text (`src/services/worker/http/routes/ViewerRoutes.ts`) points at a new Claude Code session and the logs; the `status` dependency line (`src/services/worker-service.ts`) points at `/api/health`; the onboarding explainer (`src/services/worker/onboarding-explainer.md`) and its copy in the how-it-works skill (`plugin/skills/how-it-works/SKILL.md`) give the `claude plugin` uninstall commands; the mode-creator skill (`plugin/skills/mode-creator/SKILL.md`) restarts through the installed worker script; and the Setup hook (`plugin/scripts/version-check.js`) no longer reports a missing npx install marker (a marketplace install never has one) and points version drift at `claude plugin marketplace update` / `claude plugin install`. `docs/public/telemetry.mdx` no longer tells fork users to run `npx claude-mem telemetry ...`.
- **No upstream promotion.** The cmem.ai Pro trial pitch is switched off (`PRO_PROMO_ENABLED` in `src/shared/pro-promo.ts`) and dropped cleanly from the session-start message (`src/cli/handlers/context.ts`), the context banner (`src/cli/handlers/user-message.ts`, which also loses the upstream Discord invite) and the welcome hint (`src/services/worker/http/routes/SearchRoutes.ts`). The viewer header (`src/ui/viewer/components/Header.tsx`) has no Pro trial button (`src/ui/viewer/constants/promo.ts` removed) and labels its documentation, X and Discord links as upstream claude-mem's. CMEM Pro itself still works for users who set it up.
- **Manifests.** `package.json` (and from it the plugin manifests) describes the plugin as the claude-mem-codex unofficial fork and names the author as "Ahmet Sami Gül (fork of claude-mem by Alex Newman)"; `.codex-plugin/plugin.json` shows the display name `claude-mem-codex`, a long description with the fork notice and the fork maintainer's author URL, and `scripts/sync-plugin-manifests.js` now copies those fields (with the short description) into `plugin/.codex-plugin/plugin.json`, so the root manifest is their single source. `openclaw/openclaw.plugin.json` names the same author, and the build's manifest sync gives `claude-mem-cursor/.cursor-plugin/plugin.json` and `claude-mem-grok-bot/.cursor-plugin/plugin.json` the fork's author and repository.
- **Links.** Repository, homepage and issue links in `package.json`, the plugin manifests, the OpenClaw installer (`openclaw/install.sh` clones the fork; its documented one-liner fetches the script from the fork instead of `install.cmem.ai`), the viewer's GitHub star button, the bug-report and installer error messages, `scripts/discord-release-notify.js`, the issue templates and install instructions in the docs point to the fork. OpenRouter app attribution headers now name the fork repository and title `claude-mem-codex` (`src/shared/openrouter-attribution.ts`). Links to upstream issues and pull requests, and credits, still point to upstream.
- **Telemetry off by default.** The upstream PostHog project key is removed (`src/services/telemetry/common.ts`); a transport exists only when `CLAUDE_MEM_TELEMETRY_KEY` (and optionally `CLAUDE_MEM_TELEMETRY_HOST`) is set. Consent defaults to off (`src/services/telemetry/consent.ts`), so nothing is sent without an explicit opt-in; the worker client, exception autocapture, the CLI transport and the historical backfill all follow both gates (`telemetry.ts`, `cli-telemetry.ts`, `backfill.ts`, `src/npx-cli/commands/telemetry.ts`, `src/npx-cli/commands/install.ts`). Autocaptured exceptions re-check consent and the error kill-switch in `before_send`, so a later opt-out also stops the SDK's uncaught-exception capture in a running worker. `tests/telemetry/no-network-default.test.ts` proves with the real PostHog SDK that the default configuration makes no request. `docs/public/telemetry.mdx` is updated.
- **GitHub automation.** Removed workflows that need upstream secrets or act on upstream infrastructure (`npm-publish.yml`, `deploy-install-scripts.yml`, `claude.yml`, `close-tracked-issues.yml`, `convert-feature-requests.yml`, `summary.yml`) and upstream's `FUNDING.yml`; `ci.yml` and `windows.yml` run manually only.
- **Documents.** New `README.md`; the upstream README moved unchanged to `docs/UPSTREAM_README.md`; `NOTICE` gains a fork section; `SECURITY.md` gains a fork section that routes vulnerability reports for this fork to this repository's private advisories (the upstream policy stays below it for reference); `CLAUDE.md` and `docs/i18n/README.md` note the fork; this file.
